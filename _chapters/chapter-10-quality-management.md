# 10. Quality Management

## 10.1 Purpose

Quality is built into every stage of software development rather than inspected only before release.

The objective of Quality Management is to ensure that every software increment meets functional, technical, security, and compliance requirements while supporting continuous delivery.

Quality is a shared responsibility across all roles within the Agile organization.

---

# 10.2 Quality Policy

Philips Shanghai R&D Center is committed to delivering software that is:

- Functional
- Reliable
- Secure
- Maintainable
- Testable
- Compliant
- Customer-focused

Quality shall be continuously verified throughout the software development lifecycle.

---

# 10.3 Quality Principles

The following principles guide engineering quality.

### Built-in Quality

Quality is designed into the product rather than added after development.

---

### Prevention over Detection

Defects should be prevented whenever possible.

---

### Shift Left Testing

Testing activities begin as early as possible.

---

### Automation First

Automated validation is preferred whenever practical.

---

### Continuous Feedback

Quality metrics should be continuously monitored and reviewed.

---

# 10.5 Quality Gates

The software delivery process contains multiple quality gates.

| Phase | Quality Gate |
|---------|--------------|
| Requirement | Requirement Review |
| Design | Architecture Review |
| Development | Code Review |
| Build | Automated Build Validation |
| Testing | Test Completion |
| Release | Release Readiness Review |
| Production | Operational Verification |

Each quality gate must be completed before progressing to the next stage.

---

# 10.6 Quality Assurance Activities

Quality Assurance includes:

- Requirement Review
- Architecture Review
- Test Planning
- Test Execution
- Code Review
- Security Verification
- Compliance Verification
- Release Validation

---

# 10.7 Defect Management

All defects should be recorded and managed through a common defect tracking system.

Typical workflow:

New

↓

Assigned

↓

In Progress

↓

Resolved

↓

Verified

↓

Closed

Defects should be prioritized based on business impact and customer risk.

---

# 10.8 Root Cause Analysis

High-impact defects should undergo Root Cause Analysis (RCA).

Common analysis techniques include:

- Five Whys
- Fishbone Diagram
- Fault Tree Analysis

Corrective actions should be tracked to completion.

---

# 10.9 Continuous Quality Improvement

Quality performance should be reviewed regularly.

Improvement inputs include:

- Defect Trends
- Test Coverage
- Code Quality Reports
- Customer Feedback
- Production Incidents

Outputs include:

- Improvement Backlog
- Engineering Standards Updates
- Process Improvements
