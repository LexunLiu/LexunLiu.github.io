# 12. Agile Metrics

## 12.1 Purpose

Metrics provide objective visibility into product delivery, engineering quality, team health, and business outcomes.

Metrics are intended to support learning, forecasting, and continuous improvement—not individual performance evaluation.

---

# 12.2 Principles

Metrics should:

- Support decision-making
- Encourage improvement
- Promote transparency
- Avoid driving unhealthy behavior

No single metric should be used in isolation.

---

# 12.3 Portfolio Metrics

| Metric | Description |
|---------|-------------|
| Business Value Delivered | Value achieved against planned objectives |
| Epic Progress | Progress of strategic initiatives |
| Roadmap Predictability | Alignment of delivery with roadmap commitments |

---

# 12.4 Program Metrics

| Metric | Description |
|---------|-------------|
| PI Objective Achievement | Achievement of PI objectives |
| Feature Completion | Features completed within the PI |
| Predictability Measure | Planned versus completed work |
| Dependency Resolution | Timely resolution of cross-team dependencies |

---

# 12.5 Team Metrics

| Metric | Description |
|---------|-------------|
| Velocity | Story Points completed per Sprint |
| Sprint Predictability | Planned versus completed Stories |
| Burndown | Remaining work during Sprint |
| Team Happiness | Team sentiment collected through retrospective feedback |

Velocity should be used for forecasting rather than measuring individual productivity.

---

# 12.6 Flow Metrics

| Metric | Description |
|---------|-------------|
| Lead Time | Time from request to delivery |
| Cycle Time | Time from work started to work completed |
| Throughput | Number of completed work items |
| Work in Progress | Active work items at a given time |
| Flow Efficiency | Ratio of value-added time to total elapsed time |

Flow metrics help identify bottlenecks and improve end-to-end delivery performance.

---

# 12.7 Quality Metrics

| Metric | Description |
|---------|-------------|
| Escaped Defects | Defects found after release |
| Defect Density | Defects per unit of software |
| Test Automation Rate | Percentage of automated test cases |
| Build Success Rate | Successful CI builds |
| Code Coverage | Unit test coverage where applicable |

Quality metrics should be reviewed alongside customer feedback and production stability.

---

# 12.8 DevOps Metrics

The following operational metrics align with DORA recommendations.

| Metric | Description |
|---------|-------------|
| Deployment Frequency | Frequency of successful deployments |
| Lead Time for Changes | Time from code committed to deployment |
| Mean Time to Restore (MTTR) | Average recovery time after an incident |
| Change Failure Rate | Percentage of deployments causing service degradation |

---

# 12.9 Metric Review

Metrics should be reviewed regularly at multiple organizational levels.

| Level | Review Frequency |
|--------|------------------|
| Team | Every Sprint |
| Program | Every PI |
| Portfolio | Quarterly |
